# Federated recurrence — design

**Status: design note only. Deliberately NOT built.** Nothing in this file is
implemented: no `class` field exists on `Rule`, and there is no `report` or `aggregate`
command. It is filed so the design is written down rather than re-invented, on the same
footing as [`recurrence-session-hook.md`](recurrence-session-hook.md). The five questions
in §10 are open and are the author's to decide; §11 records what the definition of done
would demand if it is ever built.

*Design written 13 September 2026. Filed the same day.*

**Where it lives:** the public `relearn` repository, Apache-2.0. Nothing here is designed
around any employer's constraints and nothing passes anyone's door.

**State when written:** 52 rules. `Rule { tag, title, error_class, home, created, origin,
status, incident, body, recurrences }`. `Recurrence { date, incident }`. `Origin::Mined |
Codified`. `Status::Active | Graduated { to, date } | Attic { .. }`. `Home::Global |
Domain { name } | Project { path }`. `Finding::OverlappingScope | HomeSlugCollision |
DanglingReference | RetiredReference | UnheldRecurrence`. Verify before building.

## 1. The thesis

**Federate the signal, not the corpus.**

The instinct is to share rules. Sharing rules requires sharing `incident`, which is a verbatim
quotation from a private working session; requires resolving two independently-written rules for
one error class into one identity; and requires retrieval once the corpus outgrows a context
window, at which point relearn stops being a compiler and becomes a search engine.

None of that is necessary to get what the idea is actually after. The valuable object is not
another engineer's rule text. It is the **number**: this error class has bitten forty-seven
installs, and you have no rule for it.

That number carries no private content, needs no entity resolution at aggregation time, and is
small enough that nothing has to be retrieved. **Federating the signal keeps relearn compiled and
deterministic.** Federating the corpus would not.

---

## 2. What crosses the boundary, and what never does

### Never leaves the machine

| Field | Why |
|---|---|
| `incident` | Verbatim quotation from a private session. This is the whole reason the naive design is unshippable |
| Every `Recurrence::incident` | Same, and there are more of them |
| `body` | Names files, functions, repository structure |
| `Home::Project { path }` | Names a project |
| `tag`, `title` | Author's own words; weakly identifying, and useless without the body |
| Any identity | No name, no email, no org, ever |

### Crosses

An **error-class identifier** from a shared published catalogue, plus counts, coarse dates, and
status kind. Nothing else.

---

## 3. The mechanism: a class catalogue, not a rule exchange

The hard question is how two installs agree they hit the same error class without exchanging
text. Fuzzy-matching `error_class` strings would require sending the strings, and would be
wrong at the edges.

**Answer: a published, versioned catalogue of error classes, and one new optional field.**

```toml
tag         = "R:verify-through-production-path"
error_class = "..."          # unchanged, local, private
class       = "EC-0042"      # NEW: which catalogue class this instantiates
```

`class` is optional. A rule without it simply does not federate — absence is not evidence, and a
corpus where every rule must map to a catalogue entry would force bad mappings.

**This is not a P2 violation, and the distinction must be stated in the design.** A catalogue
entry is a *taxonomy term*, not a rule. It has no body, no incident, no enforcement, and nothing
is compiled from it. The rule keeps exactly one home. A rule pointing at a taxonomy term is a
reference, not a second copy.

**The resolution is done by a human, once, at authoring time** — the person who wrote the rule
decides which catalogue class it instantiates. That is P4: entity resolution is the thing
machines are worst at and it is handed to the only party who knows. Aggregation afterwards is
counting, and counting cannot get it wrong.

A rule whose class is not in the catalogue is a **candidate for a new catalogue entry**, proposed
deliberately. That is how the catalogue grows, and it is the only way it grows.

## 4. The report

Generated by `relearn report`, reviewed by a human, published by a deliberate act.

```toml
schema    = 1
install   = "7f3c9a1e"     # rotating pseudonym, regenerated on demand; not a person
generated = "2026-09"      # month, not day

[[observation]]
class       = "EC-0042"
origin      = "mined"
first_seen  = "2026-08"
recurrences = 2
latest      = "2026-08"
status      = "graduated"
control     = "type"        # type | property-test | unit-test | gate | hook — the KIND, never the code
```

Note what is absent: tag, title, incident, body, path, name, repository, language.

**Dates are coarsened to the month, and that is a privacy decision rather than a formatting one.**
In a team of eight, *"someone hit EC-0042 on 28 August"* identifies a person to anyone who was in
the room. Months blur it; days do not.

**k-anonymity floor.** The aggregate publishes no class until at least *k* distinct installs have
reported it. Below the floor a count of one is a finger pointing at someone. Propose k = 5 and
make it a published constant, not a policy nobody can check.

## 5. The findings federation enables

Four new `Finding` variants, all computed against the aggregate and none requiring any foreign
text.

**`ClassRecurrentElsewhere { class, installs, local_status }`** — *Warning.* This class has
recurred for N other installs and your rule for it is still `Active`, meaning prose. Promote it.
This is `UnheldRecurrence` with the population's evidence behind it instead of only your own.

**`GraduatedElsewhere { class, installs, controls }`** — *Info.* N installs moved this class to a
stronger control, and here are the **kinds** they used. Not their code, not their tests — the
fact that four of them used a type and one used a gate. That is enough to tell you the shape of
the answer without anyone shipping anything.

**`UnminedClass { class, installs, recurrences }`** — *Info.* **This is the one the whole idea is
for.** A class with high cross-install recurrence for which this install has no rule at all. It
is wisdom arriving from people you have never met, and it is delivered as a number and a
catalogue entry, with nothing of theirs attached.

**`InertLocally { class }`** — *Info, and it is the counter-metric.* You hold a rule for a class
no other install has ever recorded. Not wrong — you may be first, or your domain may be unusual —
but a corpus full of these is a corpus of private preferences wearing the clothes of shared
engineering knowledge.

## 6. Counter-metrics — P5, and this design needs them more than anything else in the tool

**Recurrences are recorded only by people willing to write down that their rule failed.** Locally
that is uncomfortable. Published, it is worse, and the gaming path is obvious: report fewer
recurrences and look better.

Three defences, and the first two are structural rather than policy:

1. **No install is ever ranked, and the aggregate cannot rank them.** The rotating pseudonym and
   the k-floor make attribution impossible by construction. A design where the aggregator *could*
   rank installs but promises not to is a design that will eventually rank installs.
2. **Nothing is auto-published.** `relearn report` writes a file. A human reads it. Publication
   is a separate, deliberate act. If the tool syncs silently, the first person who discovers it
   syncs silently is the last person who uses it.
3. **State the confound in the output.** Cross-install recurrence measures frequency *and*
   diligence, inseparably. A class that appears rarely may be rare, or may be one nobody admits
   to. The aggregate must print that sentence beside its own numbers, because a headline figure
   without it is exactly the overclaim this project exists to prevent.

And the counter-metric to the whole scheme: **the fraction of published observations whose
`origin` is `codified` rather than `mined`.** A federation dominated by codified rules is a
federation sharing doctrine, not experience — and the author's own null result says doctrine is
the part that changes nothing.

---

## 7. Where the aggregate lives — v1 needs no infrastructure

**A git repository.** Each install opens a pull request adding or replacing its own
`reports/<install-id>.toml`. A scheduled job recomputes `aggregate.toml`. That is the whole
service.

Why this rather than a server:

- Publication is deliberate by construction — it is a pull request
- Every byte that ever crossed the boundary is in public history and auditable forever
- Human review of submissions is free, because it is code review
- No hosting, no accounts, no database, no privacy policy to write
- And if it fails, it fails as an empty repository rather than as an outage

A service can come later if volume demands it. It should not come first.

---

## 8. What must not be built

- **No automatic sync.** Ever, in any version.
- **No rule text federation in v1.** Not the body, not the incident, not even the title.
- **No identity, in any version.** Not opt-in, not hashed-but-reversible, not "for support".
- **No retrieval.** The catalogue is bounded and the aggregate is counts. The moment this design
  needs a vector index, it has become a different product and should be argued for as one.
- **No cross-install rule import.** *"47 installs hit this and here is their rule"* is the
  obvious next feature and it reintroduces every problem in §1 at once. If it is ever built, the
  rule must be re-authored locally from the catalogue entry, not copied.

---

## 9. Why this matters beyond the tool

The author's central research problem is **n = 1**: nine repositories, one author, one assistant,
one discipline, and a reviewer objection that no venue change dissolves.

Federated recurrence makes every install a potential data point, and it produces the first
measurement of a curve the third paper explicitly declines to claim:

> *"The shape is an image and not a measurement: nobody has shown the decay is geometric and this
> paper does not claim it."* — Figure 3

Cross-install recurrence against classes retired is that curve, measured. Nobody holds this data
because nobody else records corrections with mandatory provenance in a portable format.

**But a published report is not research consent.** Using the aggregate as study data requires
separate, explicit, informed opt-in, stated at the point of publication and recorded. Building
the pipeline and then deciding it is a dataset is the failure this series argues against.

## 10. Open — bring back, do not decide

1. **Who curates the catalogue?** This is the governance question and it decides whether the
   scheme works or becomes a dumping ground. A single maintainer does not scale; an open
   free-for-all produces four entries for one class, which is the entity-resolution problem
   arriving through the back door.
2. **What is k?** Proposed 5. Needs an argument, not a preference.
3. **Should `control` kind be published at all?** It is the most useful field in
   `GraduatedElsewhere` and the most likely to leak something about a codebase. Probably fine;
   worth one round of adversarial thinking.
4. **Does `class` belong on the rule, or in a separate local mapping file?** On the rule is
   simpler and keeps one home. In a mapping file keeps the catalogue dependency out of the rule
   format entirely, which matters if the catalogue is ever abandoned.
5. **What happens when a catalogue entry is merged, split or retired?** The catalogue needs its
   own versioning discipline, and it is the same problem as `Status` on rules. Do not invent it
   twice.

---

## 11. Definition of done, when this is built

All five per `CLAUDE.md`. Check 2 matters especially: `class` is a new optional field, so parse,
serialize, lint and all five emitters are touched, and the emitted tree **must not change for any
rule that has no `class`** — that round-trip assertion is what proves the existing rules were not
disturbed, exactly as it did for `recurrences`.

The federation commands (`report`, `aggregate`) write no instruction layer and must not be
reachable from `build`.

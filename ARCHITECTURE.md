# ARCHITECTURE.md — relearn

## Shape

A three-stage pipeline, with a typestate boundary between each stage so that later stages cannot receive earlier-stage data:

```
rules/*.md  ──parse──▶  Library<Unvalidated>  ──validate──▶  Library<Validated>  ──emit──▶  target files
                 │                                    │                              │
             ParseError                          ValidationError               io::Error
             (stops build)                       (stops build)                 (stops build)
```

No stage is permitted to skip a failing rule. A dropped rule is a lost correction.

## Crates / modules

| Module | Responsibility | Must NOT |
|---|---|---|
| `rule` | The neutral rule type and its newtypes (`RuleTag`, `ErrorClass`, `Incident`, `Recurrence`, `Home`, `Status`). Parsing **and** serialization (`parse_document` / `to_document`, inverses) live here. | Know anything about output formats |
| `library` | Collection semantics: uniqueness of tags, home partitioning, the typestate (`Unvalidated`/`Validated`) | Perform I/O |
| `emit` | One submodule per target: `claude`, `cursor`, `copilot`, `agents`, `claude_rules`. Pure functions `&Library<Validated> -> Vec<OutputFile>`. Shared scope/ordering/status helpers (`LoadSemantics`, `Globs`, `home_rank`, `HomeSlug`, `emittable`, `graduation_note`, `recurrence_note`) | Read the filesystem, or read anything not carried by the rule |
| `lint` | Advisory static analysis over `&Library<Validated>` → `Vec<Finding>`: overlapping scope, home-slug collision, dangling references, retired references, unheld recurrences. Reports only; findings carry a `Severity` (`Info`/`Warning`/`Error`). | Modify or delete rules, or perform I/O |
| `fsio` | All filesystem reads and writes, including the generated-file guard (write side) and the drift-detection verify (read side) | Contain business logic |
| `cli` | Argument parsing, command dispatch (`check`/`build`/`list`/`lint`/`verify`), human-readable diagnostics | Contain business logic |

The dependency direction is strictly `cli → library → rule` and `cli → emit → library`; `lint → {library, emit, rule}` (it reuses `emit::HomeSlug` because a slug collision is defined by emit's output paths); `fsio` is a leaf used by `cli` only. `emit` never touches `fsio` — emitters return values, the caller writes them. This is what makes emitters trivially testable. The `lint` module is pure and never writes: a flagged rule is input to a human decision, never auto-deleted.

## The neutral rule format

```
+++
tag        = "R:parse-wide-then-range-check"
title      = "Parse wide, then range-check"
error_class = "Range-validating by parsing into the target narrow type, making the out-of-range case unreachable"
home       = { kind = "domain", name = "rust" }
created    = "2026-07-23"     # quoted string, parsed by Date::parse (see decisions log)
origin     = "mined"       # mined | codified -- the counter-metric to recurrence
status     = { kind = "active" }
incident   = "Grouping task 01: 5/5 samples parsed into u16, so 70000 returned NotANumber; OutOfRange unreachable."
+++

Parse into a type wide enough to *represent* the out-of-range value, then range-check
to mint the narrow newtype. The perimeter must be able to see the illegal value in
order to name it illegal.
```

`status` is a sum type, so a graduated or atticked rule carries its destination:
`{ kind = "graduated", to = "hook:no-narrow-parse" }`, `{ kind = "attic", reason = "...", date = "2026-09-01" }`.

A rule that has fired **again** since it was written records each later occurrence as a
`[[recurrence]]` table, after every scalar key (a TOML array of tables captures everything
that follows it):

```
incident   = "the original, unchanged"

[[recurrence]]
date     = "2026-08-30"
incident = "Fired again: the domain-knowledge section still carried the old derivation."
```

The field is optional and absent means "has not recurred", so no rule file needed editing
when it was added — asserted byte-exactly over the whole committed corpus by
`tests/corpus.rs`.

## Type-driven decisions

- **`RuleTag`** is a newtype minted only by `RuleTag::parse`, which enforces the `R:[a-z0-9][a-z0-9-]*` shape. Nothing downstream re-checks; possessing a `RuleTag` *is* the proof.
- **`Home`** is an enum (`Global | Domain { name } | Project { path }`). One home per rule is a type-level guarantee, not a lint.
- **`Status`** is an enum carrying its payload, so "graduated" without a destination, or "attic" without a reason, cannot be constructed.
- **`Status::emittability`** is the single type home of the emit-status policy: an *exhaustive* match producing `Emittability::{Emit, Suppress}`, so a future status variant cannot compile until its emit policy is decided (rather than defaulting to "emitted" and silently leaking). Every emitter filters through `emit::emittable`, which reads it — the policy is applied in one place, not re-derived five times.
- **`Origin`** is `Mined | Codified`, mandatory, and is the counter-metric to recurrence: `Rule::is_inert` is `codified && never recurred`. A defaulted origin would classify unlabelled rules silently, which is the under-reporting the counter exists to detect.
- **`Status::Graduated` carries a `date`**, so "did this recur *since* it graduated?" is answerable at all — the question that separates a rule wanting promotion (`Warning`) from a stronger control that demonstrably did not hold (`Error`).
- **`Recurrence`** is the pair `(Date, Incident)`, not a bare `Incident` and not a second element of an `incidents` list. The triggering incident's date is the rule's `created`; a recurrence has no such field, so it carries its own. A single list would make `incidents[0]` mean something no other element means — a shape that lies about itself.
- **`Rule::new` takes `recurrences` as a required ninth argument**, not a defaulted field or a setter, so *dropping* a rule's recurrence history is a compile error at the site that drops it rather than a silent loss. Same reasoning as "a parse failure stops the build": the fact easiest to lose is the one that must be impossible to lose quietly.
- **Typestate on `Library<S>`** — `emit` accepts only `Library<Validated>`, so emitting unvalidated rules does not compile.
- **Parse wide, then range-check** applies to date fields: parse into a full date type, then constrain, so an out-of-range date reports as out-of-range rather than as a syntax error. (Dogfooding `[R:parse-wide-then-range-check]`.)

## Emission targets

| Target | Output | Notes |
|---|---|---|
| `claude` | `<out>/skills/<home>/SKILL.md` | **One skill per home layer** (not per rule — decision 2026-08-13). `<name>` is the home; `description` aggregates that home's rules for trigger coverage |
| `cursor` | `<out>/.cursor/rules/<tag-body>.mdc` | One `.mdc` per rule (Cursor's native granularity). Filename is the tag **body** (`R:foo` → `foo.mdc`) — the full tag's `:` is not a valid filename character everywhere. Front-matter `description`, `globs`, `alwaysApply` — **`globs`/`alwaysApply` derived from `Home`** via the shared `LoadSemantics` helper (domain→pattern table) in `emit`, never carried on the rule (decision 2026-08-13). Values are **not** YAML-quoted: Cursor parses `.mdc` front-matter leniently and `globs` holds a raw glob list |
| `copilot` | `<out>/.github/copilot-instructions.md` | Single concatenated file; rules ordered by home then tag |
| `agents` | `<out>/AGENTS.md` | Single concatenated file |
| `claude_rules` | `<out>/.claude/rules/<home-slug>.md` | **One file per home the target can scope** — `Home::Project` (unscoped, always resident) and known-language `Home::Domain` (scoped with `paths:`); an unknown-language domain and `Home::Global` are excluded (decision 2026-08-22). Path **derived from the home** via `HomeSlug` — decision 2026-08-22. Deliberately *not* `<out>/CLAUDE.md`: that path is the hand-authored project charter by Claude Code convention, and claiming it was a two-owner collision. A repository's own `CLAUDE.md` pulls its layer in with `@.claude/rules/<home-slug>.md` |

Every emitted file carries a generated-by header naming the source rule(s) and a hash, which is what the overwrite guard checks.

**Recurrence annotation (all targets).** A rule carrying recurrences is emitted with a
`> Has recurred <n> time(s) since it was written; most recently <date>.` blockquote under
its heading, rendered by `emit::recurrence_note` and spliced beside the graduation note.
The two are independent facts — a graduated rule that has also recurred carries both.

**Emit-status filtering (all targets).** Every emitter draws from `emit::emittable(library)`, not the raw rule set: `active` and `graduated` rules are written, `attic` rules are suppressed (a retired rule must never be written into an active instruction file). A graduated rule is emitted **annotated** — a `> Also enforced by <destination>.` blockquote under its heading — because the instruction layer tunes generation *before* it happens, a control distinct from the stronger layer that catches *after*, so the rule keeps its tuning job while flagging that a hook also holds it. The full library (atticked rules included) stays available to `lint`, which needs retired rules present to flag references to them.

## Decisions log

| Date | Decision | Why | Rejected alternative |
|---|---|---|---|
| 2026-08-13 | TOML front-matter, `+++` delimiters | `toml` crate is well maintained in Rust; YAML's Rust ecosystem is fragmented (`serde_yaml` unmaintained) | YAML front-matter — more conventional, worse maintained |
| 2026-08-13 | One file per rule, not one library file | Diffable, individually attributable, survives concurrent edits; matches "one home per rule" physically | Single `rules.toml` — simpler parse, worse provenance |
| 2026-08-13 | Emitters are pure, `fsio` writes | Makes every emitter unit-testable without a filesystem; keeps the destructive operation in one audited place | Emitters write directly — fewer types, untestable |
| 2026-08-13 | Parse failure stops the build | A silently skipped rule is a lost correction — the exact failure this project exists to prevent | Warn and continue — friendlier, unsafe |
| 2026-08-13 | Provenance fields are mandatory | The governance argument rests on provenance; optional provenance makes the tool complicit in sediment | Optional fields with defaults |
| 2026-08-13 | Type-Driven Design, not test-first | Standing doctrine (`rust-typedd`): a type constrains the whole space, a test samples points; in an AI-assisted pipeline the compiler is the cheapest retirement stage | TDD-first |
| 2026-08-13 | Claude skill emitter is one skill **per home layer**, not per rule | The skill *description* is always-resident metadata (P6, context is finite); per-rule grows it `O(rules)` and this library is built to grow. Matches the existing hand-authored skills (`project-discipline`, `rust-typedd`) which bundle many rules by domain; domain-level triggering is the right granularity. Future escape hatch: an optional `skill_group` field only if one home ever needs more than one skill. | One skill per rule — precise triggers, but unbounded resident-metadata growth |
| 2026-08-13 | Cursor `globs`/`alwaysApply` are **derived from `Home`**, not carried as target-specific fields | `Home` already *is* the neutral scoping concept; translating it into Cursor's vocabulary is the emitter's job, and vendor knowledge belongs in the emitter. Rule-level `cursor.*` fields would fragment the neutral format (every vendor then wants its own), contradicting P2. If finer scope than `Home` expresses is ever needed, enrich `Home` so every emitter benefits — never add a Cursor-only field. | Optional `cursor.*` fields on the rule — flexible, but rots the neutral format into a union of vendor front-matters |
| 2026-08-13 | Dates in front-matter are **quoted strings**, parsed by `Date::parse`, not TOML's native date literal | Preserves the `[R:parse-wide-then-range-check]` dogfood and the "out-of-range dates report as out-of-range" feature end to end: an impossible date (`2026-13-01`) must surface as `MonthOutOfRange(13)`, but a native TOML date would reject it as a *syntax* error first, collapsing the class. A quoted string reaches `Date::parse` intact. | Native TOML dates — nicer syntax, but defeats the dogfood and couples the range semantics to the TOML crate |
| 2026-08-13 | The generated-by header (marker + version + source tags + `sha256` of the body) is rendered and applied by **`fsio` at write time**, not by the emitters | Keeps every emitter a pure `&Library<Validated> → Vec<OutputFile>` body-producer with no hashing concern, and centralizes the marker format in the one module (`fsio`) that also reads it back — the writer and the overwrite-guard checker cannot drift. The emitter still supplies provenance via `OutputFile.sources`; `fsio` only serializes it. Guard placement: an HTML comment **after** the body, valid in every current (markdown-family) target and never disturbing the leading YAML front-matter of a skill or `.mdc`. | Emitters embed the header — spreads the marker format across five emitters, couples each to `sha2`, and forces the checker to trust five independent renderers to stay byte-identical |
| 2026-08-13 | The write guard is **all-or-nothing** via a pre-flight pass: check every target for the marker first, abort the whole write before touching disk if any existing target is unversioned | A single human-authored collision must never leave a half-generated tree; refusing up front is the safe failure. Matches "a dropped rule is a lost correction" applied to the write side — do not destroy unversioned content. | Write-as-you-go, error on first conflict — simpler, but leaves partial output behind |
| 2026-08-13 | **Contradiction detection is a Claude review pass** (a governance process-control), not a `lint` code check | Contradiction is a semantic judgment. Per the model-selection doctrine, intelligence-needing work is delegated to Claude through the subscription; a keyword heuristic in the linter would be a probabilistic guess sold as a deterministic guarantee — exactly the sediment the tool fights. The corpus (`rules/*.md`) is readable; Claude judges consistency periodically (first pass 2026-08-13, clean). | A keyword/similarity heuristic in `lint` — deterministic-looking, but dishonest and prone to both false positives and misses |
| 2026-08-13 | **`emit` filters by status: suppress `attic`, emit `active` + `graduated` (graduated annotated with its destination)** | A retired rule written into a live instruction file would *instruct withdrawn guidance* — the sentinel-leak failure class, one home. Graduated rules are kept, not dropped, because the instruction layer shapes generation *before* it happens whereas the graduated-to hook only catches *after*; both raise first-time-right (the metric the papers optimize), so a graduated rule keeps its tuning job — annotated so a reader knows a stronger control also holds it. Policy lives in `Status::emittability` (exhaustive match → a new status must decide) and is applied once in `emit::emittable`. | Emit every validated rule regardless of status (leaks retired guidance); or suppress `graduated` too (loses the pre-generation tuning a hook can't provide) |
| 2026-08-22 | **The project layer emits to `.claude/rules/<home-slug>.md`, one file per project home, with the path derived from `Home` — not to the constant `CLAUDE.md`** | Two defects, one root cause. (a) *The collision.* `<out>/CLAUDE.md` is the hand-authored project charter by Claude Code convention, so the emitter and a human owned one path. Bare `relearn verify` therefore exited non-zero on a clean tree and the green invocation named four of five targets — a gate whose default fails teaches every reader to add a flag, which is how a control degrades into decoration. The write-side marker guard had absorbed this correctly for months, and that is exactly why nobody looked: a guard that never fails visibly is indistinguishable from a guard that is not needed (`[R:prefer-by-construction]`; Paper 3 §8 uses this repo as the worked example). (b) *Home leakage*, found while fixing (a) and not previously recorded: the emitter filtered `Home::Project { .. }` without distinguishing *which* project, so all project homes were concatenated into one file and relearn's project layer carried stochos-lab's rules — a P2 violation in the emission layer. Deriving the path from `HomeSlug` (shape `[a-z0-9-]+` by construction) fixes both at once and leaves the emitter no free-form path with which to name a conventionally hand-authored file, so the collision is unrepresentable rather than avoided. The data needed came from the rule's own `Home`, so the "emitters read only what the rule carries" invariant is untouched. | *A different constant* (e.g. `PROJECT-RULES.md`) — swaps one collidable literal for another and leaves the leakage. *Making `Unversioned` non-fatal in `verify`* so the collision stops reporting — treats the symptom, and genuinely weakens the gate: a generated file replaced by hand-authored content would stop being reported at all. *Dropping `claude-rules` from the default target set* — hides a design decision in a default value, where the next reader will not see it |
| 2026-08-22 | **The emitted tree is committed, and CI runs `relearn verify` bare** | `verify` is the ledger's flagship gate and nothing invoked it: CI ran `fmt`/`clippy`/`test` only, and `git ls-files` returned nothing under `skills/`, `.cursor/`, `AGENTS.md` or the Copilot file, so a clean clone had no generated files for it to check. The artefact was real, correctly named and well tested, and its default invocation ran nowhere on a tree that could not have satisfied it. Paper 3 §9 names this as the sharpest limit of the enforced-by format — *the column records enforcement, not invocation* — and proposes recording the invocation and requiring it be the one CI runs. This is that, applied to the repository the paper uses as its case. Committing the tree is what gives `verify` something to verify; running it **bare** is what keeps the default path the operative one. | *Leaving the tree untracked and verifying a freshly-built tree in CI* — passes trivially, since `build` then `verify` in the same job only proves emission is deterministic (already property-tested) and would never catch the hand-edit or staleness the row claims |
| 2026-08-22 | **EOL pinned to LF for every emitted path in `.gitattributes`** | `verify` recomputes each file's body `sha256` and compares it to the hash in the file's own header. Committing the tree therefore makes line endings load-bearing: with `core.autocrlf=true` (this machine's setting, and the GitHub Actions Windows runner default) a checkout rewrites LF to CRLF, the body hashes differently, and every generated file reports `HandEdited` — green on Linux, red on Windows, for a reason nothing in the error message names. Pinned structurally rather than by teaching the hash to normalise, because the bytes on disk are what the guarantee is about (`[R:pin-eol-for-executable-text]`). | *Normalising line endings inside `render_with_header` before hashing* — makes the hash forgive a class of real edit, and hides the platform difference instead of removing it |
| 2026-08-13 | **Drift detection (`relearn verify`) compares each generated file to a fresh emission, classifying integrity *before* freshness** | "Emitted files are never sources" is a claim worth *verifying*, not just preventing. The header already hashes the **body only**, so a file's integrity is checkable against itself (body-hash vs recorded hash → `HandEdited`) with no rules needed; freshness (self-consistent but ≠ fresh emission → `Stale`) needs the rules. Checking integrity first means a hand edit is never mislabelled as mere staleness. `verify` and `build` share `cli::emit_selected`, so they cannot disagree on the expected set. Read-only: the write guard *prevents* clobbering, `verify` *detects* drift — complementary, not overlapping. | Byte-compare only (can't tell a hand edit from a stale rebuild); or re-hash without re-emitting (misses staleness vs the current rules) |
| 2026-08-22 | **`Scope` becomes the three-variant `LoadSemantics`, and the rules layer emits known-language domains scoped with `paths:`** | The pair `(globs: Vec<String>, always_apply: bool)` carried three real load models in two fields, so a fourth combination was representable and every emitter had to re-derive which of the three it held. Worse, a target that could not express one of them had no way to say so — it rendered something plausible. That is not hypothetical: `.claude/rules/` front-matter is **two-state** (absent → always; `paths:` → on reading a match), and an empty glob list has no third meaning there. Measured 2026-08-22 with an `InstructionsLoaded` hook (method in `docs/load-semantics-measurement.md`), `paths: []` loads at `session_start` — so rendering a no-glob domain "unscoped" would have promoted a rule meant to be *asked for* into one resident in every session on the machine, silently. As variants (`Always`, `WhenReading(Globs)`, `OnRequest`) with `Globs` non-empty by construction, the state cannot be built, a target that cannot represent a case must match it and decide, and a fourth load model added later is a compile error at every emitter. Cursor can say all three and does; the rules layer says two and **skips** `OnRequest`, which keeps reaching the assistant through the skill target — the mechanism that actually implements "by description". This is what makes route (c) of the `rust-typedd` homing decision real: `domain-rust` now emits to `.claude/rules/domain-rust.md` with `paths: ["**/*.rs"]`, one home, loading when Rust is touched. | *Keep the pair and special-case the empty list per emitter* — the same three-states-in-two-fields defect, now with the divergence spread across five call sites. *Emit `paths: []` for an unknown domain* — reads as "matches nothing" and behaves as "matches everything"; measured, not assumed. *Emit `Global` here too* — it is `Always` and would render fine, but it already has an always-resident home, so this would put one rule in two Claude files, which is the duplication the tool exists to prevent |
| 2026-08-22 | **`build` / `verify` take `--home <slug>`; the filter lives on `Library<Validated>` and skips re-validation** | Route (c) needs the *domain* layer emitted into `~/.claude/rules/` and nothing else. Without a filter the only way to emit that layer is `--targets claude-rules`, which also writes every **project** layer — and project homes are `LoadSemantics::Always`, so `project-relearn.md` and `project-stochos-lab.md` landing in a user scope would load unscoped in every session in every repository. That is the same promotion-to-always-on defect the `LoadSemantics` work exists to prevent, arriving through the CLI instead of the emitter. The filter is a predicate on `Library<Validated>` rather than a `Home`-shaped argument, so `library` gains no dependency on `emit`'s slug vocabulary and the layering holds. It does **not** re-validate: the only cross-rule invariant is tag uniqueness, and a subset of a set with unique tags still has unique tags, so the witness carries over by construction — stated in the doc comment beside the code, because a future invariant that does *not* survive subsetting would not be caught by the compiler. An unknown slug is an error naming the known ones, not an empty emission: `list --home` may print nothing because printing nothing is its answer, but a build that writes nothing and a `verify` that checks nothing both *report success*, which is the failure class this repository exists to catch. | *Hand-copy the emitted file into `~/.claude`* — unmanaged, no freshness gate, goes stale silently, and puts an unversioned file in a relearn-owned directory. *Accept the project layers in the user scope* — promotes project rules to machine-wide, the defect itself. *Filter the emitted `OutputFile`s by path* — works only for per-home targets and re-derives home membership from a string, exactly the sort of incidental coupling `HomeSlug` was introduced to remove |
| 2026-08-24 | **`copilot-pack/` is a second emission of the copilot target, generated and CI-verified — not a hand-assembled bundle** | The pack exists so the folder can be lifted out and dropped into an unrelated repository whose environment has no Rust toolchain and cannot run `relearn build`. A distributed copy of generated content is a staleness hazard by construction: the moment a rule changes, the copy is a confident, well-formatted lie about the library. Emitting it through the same `emit::copilot::emit` keeps it a build artefact — it carries the generated-by marker, so a hand edit hashes wrong, and `verify --targets copilot --out copilot-pack` in CI fails the build when a rule change was not rebuilt into it. The pack lies outside every relearn-owned path, so bare `verify` cannot see it and the second CI step is not redundancy but the only thing that reaches it; `.gitattributes` pins `copilot-pack/**` to LF for the same reason the root tree is pinned. The README beside it stays hand-authored and is recorded in FEATURES.md as the unenforced half — it asserts counts nothing checks. | *Commit a hand-written copy of the instructions* — no marker, no hash, no gate; goes stale on the next rule with nothing to notice. *Point users at the root `.github/copilot-instructions.md`* — no install instructions travel with it, and a single raw file is not a folder anyone can download whole. *Generate the README's numbers too* — the right end state, but it needs a rendering path the tool does not have; left open in TODO.md rather than faked |
| 2026-09-06 | **A recurrence is a separate `Vec<Recurrence>` field, not a second element of an `incidents` list** | The rule already recorded the incident that *created* it and nothing about the incident that *followed* it, so a recurring error class left two bad options: edit the original `incident`, destroying the record of what the rule was written for, or write a second rule, which is the P2 violation this tool exists to prevent. Either way recurrence — the one observation that says whether a rule is working — was lost. The two are not the same kind of thing: the first incident is *why the rule exists* and its date is `created`; a recurrence is *evidence the rule failed* and has no `created` to borrow, so it carries its own date. A single list would make `incidents[0]` mean something no other element means. A separate optional field is also backward compatible by construction: absent parses as empty, renders nothing, and no rule file needed editing — asserted byte-exactly over all forty-six by `tests/corpus.rs`, which is what turns "no migration needed" from a hope into a fact | *`incidents: Vec<Incident>`* — one field instead of two, but the first element silently means something different from the rest, and the recurrence dates have nowhere to live. *A `Default` field or a `with_recurrences` setter* — spares nineteen call sites the `Vec::new()`, at the cost of making a dropped recurrence history silent in the parser or in any future transform |
| 2026-09-06 | **`UnheldRecurrence` is `Warning`, with no count threshold, and does not fire for a graduated rule** | *Warning, not Error*: `Error` in this lint means the emitted tree would be wrong — two rules colliding on one output file — and a build that emits correctly should not fail. An unheld recurrence is a fault in the **library**, which is a different thing. *No threshold*: the first recurrence already proves the prose failed, two is not more actionable than one, and a cut-off would be a magic number this codebase does not use. *Not for graduated rules*: a recurrence **after** a graduation is the sharper finding — the named stronger control was claimed to hold this and demonstrably did not, a lying artefact and an `Error` rather than a `Warning` — but it needs a graduation **date**, which `Status::Graduated { to }` does not carry; adding one touches status parsing and serialisation for every rule file. Flagging it here as an ordinary `UnheldRecurrence` would say the wrong thing (the rule is *not* held by prose alone) and pre-empt the finding it deserves | *`Error` severity* — fails a build whose output is correct, and teaches readers to pass a flag, which is how a gate degrades into decoration. *A `>= 2` threshold* — invents a number nothing justifies. *One finding covering both statuses* — merges two findings with different severities and different remedies into one that is accurate for neither |
| 2026-09-06 | **The recurrence metric ships with its counter-metric recorded as `NOTHING YET — exposed`, not computed** | P5 requires every metric to carry a counter-metric, and this one's gaming path is plain: recurrences are recorded only by someone willing to write down that their own rule failed, so the number falls through under-reporting exactly as easily as through prevention. The counter is the corpus's *inert* fraction — rules that never recurred **and** were never mined from a real failure — and the null result says those are the rules that change nothing (*"you cannot author your way to a delta"*), so a library that looks healthy because it is full of them is the failure this metric would hide. It cannot be computed today: codification-dating is a prose convention, not a field, and making it one needs an `origin: Mined \| Codified` — a second modelled fact with its own argument. Using the exposure mechanism is the honest alternative to either violating P5 or doubling the scope | *Inventing `origin` in this change* — doubles the scope and settles a modelling question in passing. *Shipping the metric unaccompanied* — violates P5 silently, in the repository whose subject is not doing that |
| 2026-09-06 | **`relearn lint --deny <warning\|error>`, defaulting to `warning`; CI runs `--deny error`** | Adding the first recurrence row made `lint` exit 1, which exposed a policy that had never been tested against a long-lived finding. Every finding until then was a structural defect fixable by editing the library — a slug collision, a dangling citation — so "any actionable finding fails the run" was correct by accident. `UnheldRecurrence` is different in kind: it reports that a rule needs **promoting to a stronger control**, and the control may have to be built in another repository, so the finding legitimately stands for weeks. `lint`'s own module doc already says findings are "reported, never acted on — input to a human cut-list decision", and a human decision is not a CI gate.
